# www.stryker.com → EDS migration: status, approach and results (2026-10-28)

Purpose: a reviewable account of everything built for the corp (www.stryker.com) migration so
far, what it is based on, what it produces and how well. Read this to judge the approach before
the remaining templates are built the same way. Everything below is in git (branches listed in
§5), except the imported content, which exists only as local files (§6).

Work on the remaining plan (other templates, re-imports, PRs) is **on hold** until this review.

---

## 3. Architecture, top to bottom

```
.migration/ exports ──► migration index (generated) ──► decision tables (approved)
                                │                              │
                                ▼                              ▼
          tools/importer/data/*  (bundled)        tools/importer/decisions/*
                                │                              │
                                └────────► shared import engine ◄─┘
                                       corp-page.js
                                       corp-section-builder.js   (sections + Section Metadata)
                                       corp-component-handlers.js (one handler per component-map row)
                                       corp-richtext.js          (typography rules)
                                       corp-components.js        (images, XF matching, CF cards)
                                                │
              ┌─────────────────────────────────┼───────────────────────────┐
              ▼                                 ▼                           ▼
   import-product-detail.js           import-xf-fragments.js      import-cf-fragments.js
   (pages; one per template)          (XF fragment documents)     (content-fragment documents)
              │                                 │                           │
              └──────────► local content ◄──────┴───────────────────────────┘
                                │
                     check-coverage.js (authored text vs output, 404 detection)
                     + render comparison against the live page (pilot)
                                │
                     EDS blocks / section styles / template CSS render it
```

### 3.1 Migration index — `tools/importer/migration-index/` (`npm run build:migration-index`)
Turns the exports into data the browser-based importer can bundle (it cannot read `.migration/`).
Outputs (never edited by hand):
- `data/xf-index.js` — every XF variation: EDS path, status, nested XFs, content fragments, DM assets, usage; per page the XF references in authored order (fragment or hero slide, desktop/mobile); skipped references.
- `data/cf-index.js` — content fragments, their fields and which fields each use shows.
- `data/page-facts/<template>.js` — per page: metadata (title, description, share image + alt, tags, publish dates, content ID), anchors incl. hidden section titles, disclaimer, Marketo forms, tab titles, card-list targets, interactive-image hotspots, images without alt.
- `data/catalog/` — decision catalogs: `typography.json` (1,122 formatting combinations), `components.json` (93 component types), `site.json` (every page with its template and migration state), `xf-report.json`, URL lists per template for the XF / CF importers.
- `check-coverage.js` — after every import: lists authored text missing from the output; text not on the live page is reported as author-only and does not fail; fails pages where the import fetched a 404.
- `xf-fragment-path.js` / `xf-path-rule.js` — the single XF → EDS path rule (`/content/experience-fragments/…` → `/us/en/fragments/…`, lowercase, `_` → `-`); tested against all 1,180 variations (0 collisions).

### 3.2 Decision tables — `tools/importer/decisions/` (all approved, §8)
- `typography-map.json` — 21 rules: how each rich-text formatting becomes EDS authoring (Appendix B).
- `component-map.json` — all 93 AEM component types → block / variant / section style / default content / skip, with counts, evidence, example page (Appendix A); 34 new names approved (Appendix C).
- `site-classification.json` — 21 templates, page counts, import order, re-import rule, pilot rule (§11).
- `content-fragments.json` — content fragments become their own documents; the card shows the fields the live page shows, the rest is kept as metadata.
- `open-questions.md` — the review document you approved ("approve all recommendations"); client inputs still open.

### 3.3 Shared import engine (corp section builder)
- Walks the rendered page component by component in authored order; each component has a handler that returns items (text, image, block, fragment, form, anchor, boundary).
- The builder places items into sections and writes Section Metadata (styles, anchor id). New section when the copy style changes, a serif/Futura heading switch, a heading-size change, a separator, a column-control boundary, a block that needs its own section.
- XFs rendered on the page are matched to the index (authored order + text) and become Fragment blocks pointing at the fragment document; unmatched XFs stay inline and are reported.
- Hero carousels: one Hero Corp per slide; slide images that are XFs become links to their fragment documents (desktop + mobile).
- Every importer reports what it could not reproduce (unhandled components, dropped anchors, mixed styles, missing alt text) — nothing is silently lost.
- Link rewriting (`.html` dropped, `index.html` → `/`) runs once in the shared cleanup transformer.

### 3.4 Template importers
- `import-news-detail.js` — existed before (79 news pages); now also uses the shared rich-text rules, XF → Fragment blocks, page facts metadata.
- `import-product-detail.js` — **new**, the first importer on the shared engine (pilot, §7).
- `import-xf-fragments.js` — **new**: XF fragment documents. News XFs keep the news rules; the 7 styled shared news fragments are delegated to the existing importer unchanged; every other XF uses the section builder.
- `import-cf-fragments.js` — **new**: one contact-card document per content fragment.

## 4. Authoring approach (what an author sees and edits in DA)

A migrated corp page is a normal EDS document. Nothing is generated at runtime except where noted.

### 4.1 Page structure
- **Sections** separated by `---`, each with an optional **Section Metadata** `style` row. Styles carry everything that is "how this region looks": background band, copy size, serif, label size, heading size, alignment, divider, layout.
- **Default content** for rich text, images, headings, buttons (authored with the formatting conventions: bold link = button, bold + italic = Futura bold, underline heading = rule below, a link alone on its line = CTA).
- **Blocks** only where the content has structure: Columns, Cards Corp, Hero Corp, Accordion, Tabs, Table, Statistics, Video, Marketo Form, Sticky Nav, Fragment.
- **Fragments**: every XF is its own document at `/us/en/fragments/<AEM path>` and is placed on the page with a Fragment block. A fragment used by many pages exists once (837 XFs site-wide, 97 shared variations). Hero slide images and videos are fragment documents too (linked from the Hero Corp rows).
- **Content fragments** (contact boxes): one document each at `/us/en/fragments/content-fragments/<path>`, a Cards (contact) card with the fields the live page shows; the other fields + labels as a Metadata block (never rendered).
- **Page metadata** (from the exports): title, description, image, keywords, `site: corp`, `template`, published, `content-id`, `tags`, `originally-published`, `image-alt`, `hcp-banner`.

### 4.2 Section-style vocabulary (corp, `styles/styles-corp.css`)
| Group | Styles | Meaning |
|---|---|---|
| Copy size | `p-0-8`, `p-1`, `p-1-25`, `p-1-5`, `p-1-75`, `p-2`, `p-2-5` | paragraphs / list items at 0.8–2.5× (stryker.com `fontsize-<x>em`) |
| Copy font | `serif`, `bold-body` | Egyptienne copy; plain bold in the body font (Humanist) |
| Headings | `h-serif`, `h-1-25`, `h-1-5` | h2/h3 in Egyptienne Light; h2/h3 at 1.25× / 1.5× the template's plain size |
| Labels | `label-1-5`, `label-1-75`, `label-2` | a fully bold paragraph (label) at 21 / 24.5 / 28px when larger than its copy |
| Bands | `bg-gold`, `bg-gray`, `bg-light-gray`, `bg-dark-gray`, `bg-white`, `bg-dark-purple-gradient`, `bg-dark-blue-gradient`, `bg-golden-gradient`, `dark`, `connect-band`, `talent-banner` | background panels |
| Layout | `flex`, `flex-67-33`, `flex-33-67`, `center`, `divider`, `large-headline`, `contact-aside`, `disclaimer`, `ps-0`, `ps-1` | side-by-side blocks, alignment, rules, headline scale, contact asides, spacing |

New in this work: `p-0-8`, `p-2`, `p-2-5`, `bg-gray`, the three gradients, `flex-67-33`, `flex-33-67`, `large-headline`, `label-1-75`, `label-2`, `h-1-25`, `h-1-5` (all approved). `bold-body`, `serif`, the copy sizes and labels now also apply inside blocks and nested fragments.

### 4.3 Block options added (all approved)
- **Hero Corp** `image-slide`: `top-/bottom-/left-/right-<n>` text box, `size-<n>` (vw headline), `copy-size-<n>` (vw copy, now in every text box), `text-below`, `text-above`, `bottom-<n>`, **`image-right`** (product hero: image in the right half from 600px), **video slides** (a slide fragment holding a video plays as a muted looping background).
- **Columns**: `page-intro` (corp page hero), plus existing corp modifiers (`large-headline`, `gold-first`, `gray-lead`, `boxed-last`, `media-pair`, `related-links`).
- **Cards**: `contact` (content-fragment boxes).
- **Sticky Nav**: `local` (stryker.com local page navigation / jump bar).

### 4.4 What is runtime (not authored)
- News list, event calendar, site map: built from the query index (needs `published`, `tags`, `event-*`, `robots` columns — §10).
- Charts: rendered as inline SVG from an authored table.
- Linked DM images: authored as a link whose title is the image URL; rendered inside the link.

## 9. Known limitations and normalisations
- **Source variety**: product-detail has 449 distinct component sets over 677 pages (13% in the top 3). The engine handles components generically, but every new page can surface an unhandled combination; the importer reports them instead of guessing.
- **Per-line hero sizes, Large Headline sizes, one-page patterns** are normalised (above).
- **Video heroes**: the background video is the same for desktop and mobile when the source has one variation; the 1788 mobile variation was never published (reported, not invented).
- **Tag crumb "Related categories"** (visible on 63 pages) is imported as `tags` metadata, not shown (approved component rule).
- **Share image** (`Image` metadata) is empty on all 6 pilot pages although the page facts collect a share image — an importer gap to fix before the full run.
- **Local fragment copies**: running importers rewrites local fragment documents that other pages share (DA untouched).
- **News re-import impact**: shared rules changed since the 79 news pages were migrated (serif h2/h3 rule, label colour, bold-body, heading sizes). The news importer bundle has not been rebuilt; re-importing news will need the planned diff step.
- **Block Library**: entries for the new options, styles and blocks are not written yet (DA content).

## 10. Open inputs and external dependencies
- Marketo form IDs for 47 division contact pages + 2 corporate (client).
- Microapps (`remotecomponent`, 30 uses) only allow framing from `*.stryker.com` (client must add EDS hosts to frame-ancestors).
- Marketo forms are framed over `http://` and blocked by the site CSP (needs `https` form URLs).
- Query index columns `published`, `tags`, `event-*`, `robots` for the news list, event calendar and site map (site config).
- Google Maps: keyless embed in use; Stryker's key would need the EDS hosts in its referrer list.
- The old `a-message-to-our-customers` fragment document in DA is orphaned by a path move (manual cleanup).

| heading-serif | h2 / h3 set in span.urw-egyptienne (whole heading, no bold) | section style h-serif (Egyptienne Light); a Futura h2 / h3 in the same run starts a new section | established (h3) + approved (h2) |
